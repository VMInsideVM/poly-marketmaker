# 钱包备注全站优先显示

日期：2026-07-24

## 背景

钱包备注（`wallets.remark`，纯展示字段）已经在仪表盘、历史、实时监控三处的表格里生效，靠的是 `web/static/app.js` 的 `walletLabel(remark, addr)`：有备注就显示备注，没有就显示 `0x1234...abcd` 短地址，完整地址放进 `title` 悬浮。

还有地方在裸显示地址。`orders.html`（挂单与持仓）完全没接备注，挂单表钱包列、持仓表钱包列、钱包筛选下拉、"部分钱包拉取失败"的错误提示，四处都是手写的 `addr.slice(0,6) + '...' + addr.slice(-4)`。`history.html`、`logs.html`、`pnl.html` 的钱包下拉用的是「备注 (短地址)」，和同一页表格里的 `walletLabel` 不是一个口径。

用户要求：前端凡是显示钱包地址的地方，都优先显示备注名。

## 目标

1. 挂单与持仓页的四处地址显示接上备注。
2. 全站下拉统一成 `walletLabel` 口径，有备注只显示备注，无备注显示短地址。
3. 无备注时的显示不变（短地址），完整地址仍可悬浮查看。

## 不做

- 配置页（钱包管理表）的地址列保持原样。那页是管钱包的，地址本身就是管理对象，旁边已经有独立的备注列可编辑。
- 后端不动，`/api/orders`、`/api/positions` 不新增 `remark` 字段。
- 不碰备注的写入链路（`/api/wallets/<address>/remark` 已有）。

## 方案

备注只能从 `/api/wallets` 拿，该接口返回的每个钱包都带 `remark`。三种取数方式：

1. 每页各自建 `_remarkByAddr` 映射，orders 页照抄 history/logs 那段。改动最小，但同一段样板要写第四遍。
2. 后端在 `/api/orders`、`/api/positions` 的每一行塞 `remark`。没有时序问题，但要改两个路由加契约测试，每行多带一个纯展示字段。
3. **映射提到 `app.js` 共享**（采用）。后端零改动，orders 页直接用，顺手把 history/logs 里重复的两份 `_remarkByAddr` 收敛掉。

### `app.js` 新增

```js
// addr(小写) -> remark，全页面共享一次 fetch
function walletRemarks()      // -> Promise<Map>，内部缓存 promise，重复调用不重复请求
function walletLabelOf(addr)  // 同步查缓存；缓存未就绪时退回短地址
```

地址统一转小写做 key。DB 里存的地址和各接口回传的地址来源不同，大小写有可能对不上，小写归一能防止查不到备注而静默退回短地址。

`walletLabel(remark, addr)` 保留不动。仪表盘拿到的钱包数据本身就带 `remark`，不需要走缓存。

### 各页改动

| 文件 | 改动 |
|---|---|
| `web/static/app.js` | 加 `walletRemarks()` / `walletLabelOf()` |
| `orders.html` | 挂单表钱包列、持仓表钱包列、筛选下拉、错误提示四处改成备注优先，完整地址进 `title`；首屏渲染前先 await 映射，避免闪一下短地址再变备注 |
| `history.html` | 下拉改成只显示备注；本地 `_remarkByAddr` 换成共享映射 |
| `logs.html` | 同 history |
| `pnl.html` | 下拉改成只显示备注 |

## 验证

- `node --check` 过 `app.js` 和各模板抽出来的 script 块。模板含中文，要防别字和 BOM。
- `pytest` 全绿，确认后端没被碰坏。
- 启动 app 人工走查：挂单与持仓页的两张表和下拉、历史页、实时监控页、盈亏台账页。
- 边界：给一个钱包留空备注，确认它仍显示短地址；改完备注切页刷新，确认新备注生效。
