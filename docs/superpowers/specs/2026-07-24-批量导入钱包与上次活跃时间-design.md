# 批量导入钱包 + 上次活跃时间

日期：2026-07-24

两个独立的小功能，都围绕钱包，放在同一份 spec 里。

---

## 一、批量导入钱包

### 现状

配置页「钱包管理」一次只能导一个：填私钥（可选存款地址 / 代理 / 备注），`POST /api/wallets/preview` 先算出自动识别的存款地址，弹窗让用户跟 polymarket.com 逐字比对，确认后 `POST /api/wallets` 真正入库。入库这一步会探代理协议（`probe_proxy`，先 HTTP 后 SOCKS5，不通就拒绝保存）、探账户类型（`balance_by_sig_types` 逐个 sig 查余额，有钱的那个就是真实类型），然后加密私钥写库。

钱包一多，一个一个导太慢。

### 输入格式

一行一个钱包，逗号分隔：

```
私钥,代理,备注
```

代理和备注可省，空行忽略。合法的四种写法：

```
0xabc...def,1.2.3.4:8080:user:pass,主号
0x456...012,1.2.3.5:8080:user:pass,小号2
0x789...345,,小号3
0xdef...678
```

分隔符不能用冒号，代理串本身就是 `host:port:账户:密码`。存款地址不在批量格式里，一律自动识别；识别不对的钱包（智能合约 / 邮箱钱包）导完删掉，单独用现有的单个导入补。

### 流程

前端把 textarea 原文 POST 给 `/api/wallets/import`，提交后立刻清空 textarea，私钥不在页面上多停留。

后端起一个后台线程串行逐行导入，请求本身立刻返回。前端每秒轮询 `/api/wallets/import-status` 拿进度和逐行结果，结束后刷新钱包列表。这跟现有的扫描进度指示器（`/api/engine/scan-status` + 侧边栏）是同一个路子。

单个导入的入库逻辑抽成一个内部函数 `_import_wallet(private_key, funder, proxy, remark)`，返回成功信息或抛错。`api_add_wallet` 和批量导入都调它，保证两条路完全一致，不出现「批量导进来的钱包跟单个导的不一样」。

### 逐行结果

每行给出：行号、备注、钱包地址、存款地址、代理协议和出口 IP、结果。失败行标原因，不影响其他行：

- 格式错误（字段数不对、私钥不是 64 位十六进制）
- 私钥无效
- 代理不可用
- 该钱包已存在

### 耗时

每个钱包要探代理（最多两次握手）加 4 次余额查询，实测量级 5 到 15 秒。串行 10 个约一到两分钟，进度条能看到跑到第几个。先不做并发，YAGNI。

### 安全

私钥在 textarea 里是明文（多行输入没法用 password 框遮）。缓解手段：提交后立刻清空 textarea，界面上写一句提醒。进度和结果都不回传私钥。

## 二、上次活跃时间

### 定义

「活跃」指这个钱包真干了活：成功挂出一笔买单，或者有一笔成交。覆盖式，只留最近一次，不记历史。

### 存储

`wallets` 表加一列：

```sql
last_active_at REAL NOT NULL DEFAULT 0
```

沿用现有的 `ALTER TABLE ... ADD COLUMN` 迁移写法（见 `remark` 列）。`db.touch_wallet_active(address)` 一句 UPDATE。

### 写入点

1. `engine/manager.py` `place_orders` 里 `placed += 1` 那一刻（`place_limit_buy` 成功返回后）
2. `engine/monitor.py` `_handle_fill` 抓到成交那一刻

两处都包 try/except，写库失败只打 warning。这一列纯展示，绝不能因为它影响下单或止损。

### 显示

仪表盘钱包表新增一列「上次活跃」，相对时间：`刚刚` / `3 分钟前` / `2 小时前` / `3 天前`，从没活跃过显示 `—`。完整时间放 `title` 悬浮。

配置页那张表是管配置的，不重复放。

`/api/status` 的 `wallet_summaries` 带上 `last_active_at`（秒级时间戳），前端格式化。相对时间格式化函数放 `app.js`，纯函数好测。

## 验证

- 单元测试：批量导入的行解析（`parse_import_lines`，纯函数，覆盖四种合法写法 + 空行 + 字段数超标 + 全空）；相对时间格式化。
- `pytest` 全绿。
- `node --check` 过改动模板抽出的 script 块，无 BOM。
- 人工走查：导两个钱包（一个带代理一个不带），看进度和结果表；故意混一行坏私钥和一个重复钱包，确认其他行照常入库；启动引擎挂出买单后看仪表盘的上次活跃列。
