范围：2026-08-14 三个改动（`dd97719` 断层全簿口径、`7067cf2` 三级高位闸门、`3286e38` 老策略可切换模式）及其与现有代码的交互。12 轮假设-实验，全部结论有可复现的实验证据。

基线：1079 测试全绿，无已知故障。以下问题**测试全绿也发现不了**。

## HIGH-1 清空策略表单任一数字框 → 该钱包永久静默停止交易

**这是既有缺陷，不是本次引入**；本次改动只是又多了三个可触发的输入框。

- **位置**：`web/templates/config.html` 的 `strategy-form` 提交处（`data[inp.name] = parseFloat(inp.value)`，无 `isNaN` 过滤）+ `engine/manager.py` 的 `int(tmpl.get("...", 默认))`
- **链路**：清空输入框 → `parseFloat('')` = `NaN` → `JSON.stringify` 转成 `null` → 后端 PUT 返回 **200**、`null` 落库 → 下一轮 `int(None)` 抛 `TypeError` → `place_orders` 调用点只有 `except Exception: logger.error(...)` → **该钱包每一轮都失败，UI 上没有任何提示**
- **实验证据**：
  ```
  PUT /api/templates/<id> {"legacy_wall_threshold": null} -> 200
  落库读回 legacy_wall_threshold = None
  place_orders -> TypeError: int() argument must be ... not 'NoneType'
  ```
- **受影响的键**（全部实测崩溃）：既有的 `gap_wide_cents`、`gap_mid_cents`、`cliff_probe_cents`、`max_exposure_usd`、`max_concurrent_markets`；本次新增的 `legacy_wall_threshold`、`legacy_cumulative_threshold`、`order_size_custom_usd`
- **对照**：`engine-form` 的提交处**有** `if (!isNaN(v))` 过滤，所以引擎参数不受影响。两个表单写法不一致。
- **建议**：`strategy-form` 照抄 `engine-form` 的 `isNaN` 过滤（一行）；后端 `int(...)` 改成 `int(... or 默认值)` 做纵深防御。

## MEDIUM-2 老策略记账与预演写的份数不是实际挂单份数

- **位置**：`engine/manager.py` 的 legacy 分支把**钱包总余额**传给 `explain_legacy_order`，而实际份数来自 `compute_market_legacy_orders`（被市场预算/敞口封顶）。记账文案取自前者。`web/routes.py` 的预演分支同理。
- **实验证据**（端到端跑 `place_orders`）：
  ```
  实际挂单份数(发给交易所): 500
  actions.size 列(结构化)  : 500     ← 正确
  actions.reason 文案      : ...× 3448份   ← 错
  actions.price_basis 文案 : ...× 3448份   ← 错
  ```
- **触发条件**：`order_size_mode` 为 `custom` 或 `balance` 且实际被封顶。默认 `min` 模式两边都返回 `min_size`，一致，不触发。
- **性质**：与本轮已修的三个「记账说谎」同类——结构化字段对，人读的文案错。
- **建议**：记账与预演改用封顶后的份数，或在文案里标注「上限 N 份，实挂以 size 列为准」。

## MEDIUM-3 历史页把老策略的跳过标成「断层单档」

- **位置**：`web/templates/history.html:58` — `gap_skip: '断层单档·判定不挂'`
- **原因**：设计时决定两种模式复用同一个 `gap_skip` 动作类型（避免新增类型），但没改标签文案。
- **后果**：用户切到老策略后，历史页所有跳过记录都标着另一套策略的名字。reason 正文是对的（写着「厚墙…」），只有标签错。
- **建议**：标签改成中性的「判定不挂」，或按 reason 前缀区分。

## MEDIUM-4 balance/custom 份数模式下余额一变就全部撤单重挂

- **位置**：`engine/legacy_wall.py` 的份数随余额线性变化 + `engine/laddering.py` `reconcile_buy_orders` 的容差 `max(1, 1%)`
- **实验证据**（`max_exposure_usd=250`、价 0.29）：
  ```
  余额 300 → 250 → 200 → 150 → 145   目标份数恒 500(被敞口封顶)  保持
  余额 145 → 140                      500 → 482                  撤单重挂
  余额 100 → 95                       344 → 327                  撤单重挂
  ```
- **边界**：余额 ≥ `max_exposure_usd` 时市场预算恒定，份数不变，**不受影响**。只打小余额钱包。
- **后果**：做市中成交会不断改变余额 → 反复撤单重挂 → 丢失队列位置 → 奖励减少。
- **性质**：v1.0.15 没有撤改收敛机制，这是移植进当前架构后才出现的新组合。
- **建议**：老策略 + 非 `min` 模式时放大 reconcile 容差，或把份数按预算而非余额算（预算被 `max_exposure_usd` 钳住后天然稳定）。

## LOW-5 老策略挂单成功时把整个买单簿写进 DB

- **位置**：`engine/legacy_wall.py` `legacy_price_basis` 无论挂单还是跳过都展开全部 `levels`；`gap_single_price_basis` 只在跳过时展开，挂单时只写选中档。
- **实验证据**（40 档买单簿，挂单成功时）：老策略 **920 字符**，gap_single **102 字符**。
- **后果**：每次挂单都写长文本，`actions` 表膨胀，历史页难读。挂单是高频操作（每 30 秒一轮 × 多市场 × 多钱包）。
- **建议**：挂单成功时只写命中档与选中档，跳过时才展开全簿（对齐 gap_single 的做法）。

## LOW-6 悬崖否决时预演页显示错误的规则标签

- **位置**：`engine/legacy_wall.py` 的悬崖判定在 `rule`/`threshold` 赋值**之前** return，两者为 `None`；`web/templates/markets.html` 的 `renderLegacyWall` 用三元 `s.rule === 'cumulative' ? '累计厚度（0.1 美分盘）' : '厚墙（1 美分盘）'`，`None` 落到 else。
- **实验证据**：
  ```
  0.1美分盘·无悬崖: rule='cumulative' threshold=6000   → 标签正确
  0.1美分盘·悬崖  : rule=None        threshold=None    → 显示「厚墙（1 美分盘）· 阈值 —」(错)
  ```
- **对比**：gap_single 用 `_GAP_RULE_LABEL.get(rule, "无区间档")`，未知时显示中性文案，不会声称是某个具体规则。
- **建议**：`renderLegacyWall` 加 `None` 分支。

## LOW-7 逐档挂量是小数、累计是整数，并排显示对不上

- **实验证据**：`0.2100×236.24(累计236) · 0.1900×120(累计356) · 0.0800×9.14(累计365)`，而 236.24+120+9.14 = 365.38
- **原因**：累计用 `cumulative += int(float(size))`，是 v1.0.15 的原版行为，**判定逻辑不能改**（改了就不忠实原版）。这纯粹是显示问题。
- **建议**：显示时把逐档 size 也取整，或在表头注明「累计按整数份计」。

# 重要发现（非代码缺陷，但影响实际效果）

## A. 旧口径下规则1 在结构上永远不可能触发 —— 这才是最初问题的完整根因

奖励区间宽度 = `2 × max_spread_cents`，所以**旧口径下「区间内的最大断层」有硬上界**：

| max_spread | 区间宽度 | 区间内 max_gap 上限 | 旧口径能归规则1吗（需 >10¢） |
|---|---|---|---|
| 2¢ | 4¢ | ≤ 4¢ | 不可能 |
| 3¢ | 6¢ | ≤ 6¢ | 不可能 |
| **4¢**（用户实配） | **8¢** | **≤ 8¢** | **不可能** |
| 5¢ | 10¢ | ≤ 10¢ | 不可能 |
| 6¢ | 12¢ | ≤ 12¢ | 可能 |

用户模板配的是 `max_spread_cents=4`，所以**规则1 一次都没执行过**，`gap_high_coeff_sum_min=20` 这个参数从来没起过作用。最初报的「规则1厚度要求没有执行」不是那一个地震市场的特例，是配置下的必然结果。当时的诊断（「区间内只剩一档 → max_gap=0 → 落到规则3」）是对的，但只说了一半。

## B. 新口径下分级反转，刚加的规则2/3 闸门几乎不会触发

全簿口径下，低价区稀疏必然制造 >10¢ 断层，市场几乎恒为规则1。于是 `rule2_high_coeff_sum_min` / `rule3_high_coeff_sum_min`（昨天刚加的功能）在实际盘口上几乎没有触发机会。断层改动时已量化过「规则2/3 实质废弃」并获用户确认，但三级闸门是在那之后才加的，这层交互当时没有被点破。

## C. 老策略的默认阈值 2000/6000 相对当前盘口量级可能过高

唯一的实盘数据点（用户截图的地震市场）最厚的档是 **236.24 份**，而 1 美分盘的默认厚墙阈值是 **2000**。按此量级，切到老策略后大量市场会判「无档达到阈值 → 整市场不挂」。阈值是可配的，默认值忠实 v1.0.15，但 v1.0.15 时代的盘口量级与现在未必可比。切换后建议先用预演页观察实际盘口的挂量分布再定阈值。

## D. 切换模式瞬间会撤光在挂买单

实验确认：老策略判不挂时目标挂单为空，`reconcile_buy_orders([], resting)` 撤掉该侧全部在挂买单。这是撤改收敛的既有语义（与停用档位模块时一致），但配合 C 项（阈值偏高导致大面积不挂），切换瞬间的冲击会很明显。

# 未能证实的理论风险

**老策略的定价依赖 `tick_size` 判粗细盘**，这是 gap_single 没有的新依赖（gap_single 只把 `tick_size` 透传给下单，定价用美分）。`manager` 里取值为 `float(ob.get("tick_size", "0.01") or 0.01)`，若订单簿响应缺该字段，0.1 美分盘会被当作 1 美分盘、走错定价路径（用 2000 单档阈值而非 6000 累计阈值）。`get_orderbook` 直接透传 CLOB client 的返回，离线无法验证生产响应是否总带该字段。需要实盘抽查一次订单簿响应确认。

# 已验证无问题

- **核心不变量**：4000 组随机盘口（随机 tick / 档数 / 价格 / max_spread / 份数模式 / 阈值 / 悬崖开关）产生 1399 笔挂单，**挂价全部落在奖励区间内、份数全部不低于最低份额**，零违规。
- **gap_single 零回归**：三级闸门与老策略改动均未触及 gap_single 的决策路径（`git diff -w` 显示只有缩进）。
- **选 custom 模式忘填金额**：会全部不挂，但 `gap_skip` 记录写明了「按份数模式 custom 算出的份数不足最低份数 20」，有清晰解释，不算缺陷。
- **配置页切模式不丢参数**：`querySelectorAll` 不受 `display:none` 影响，隐藏的那套参数照常提交。
- **老策略与选品、黑名单、UMA 结算守卫、单侧暂停的交互**：这些判定都在模式分支之前，两种模式共用。
